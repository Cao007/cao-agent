# AI 客服应用：需求与验收

来源：[功能展示：MewHelp 能干什么](https://ycnipcoc81qb.feishu.cn/wiki/A7ymwy96di7c3YkQYjccuRLVnAb)，文档版本 4。
开发分支：`feat/ai-customer-service`。

用户已授权基于现有框架开发新项目，用本次业务检验 FastAPI、编排与 Vue 三层扩展路径。
关联的另一篇架构设计文档当前无访问权限，不作为推进的阻塞条件。

## 客服交互

1. 知识问答：按语义找到规则，回答标注引用编号，能查看具体知识片段。
2. 业务查询：官方 Agent 自主调用订单工具和物流工具；页面展示可公开的工具过程。
3. 多轮对话：上一轮查询订单后，“它能退吗”关联到该订单。
4. 退款研判：确定性流程先取得订单、再检索退货政策，最后生成带政策依据的判断。
   本次只研判是否可退，不实际提交退款或变更订单。
5. 置信度不足：绕过模型生成，明确不知道，提供人工接管入口，问题进入待审池。
6. 订单不明确：使用 LangGraph interrupt 暂停，展示本人订单供点选，再恢复原流程。
7. 用户可点赞、点踩；点踩与未解决的问题进入可审核的知识反馈链路。

## 运营后台

- 总览六块：知识库、RAG 评估、飞轮待审、观测与成本、主题分布、分类器验收。
- 知识库：录入和管理知识，切块、向量化，展示类型、状态和索引进度。
- RAG 评估：比较关键词、向量、混合、混合加重排四种策略；
  计算 Recall、MRR、覆盖度，支持评估数据更新和重新运行。
- 待审队列：审核问题、补写可靠答案、通过后加入知识库并索引；支持驳回与过期处理。
- 观测与成本：按意图统计调用与 token，区分实测用量、配置价格估算和未知成本；
  比较在用与评估推荐的置信度阈值。
- 主题分布、分类器验收：由实际会话及带标签的评估记录计算，未运行时显示未运行。

## 实施边界

沿用当前框架 PostgreSQL，不额外引入参考系统的 MySQL 与 Milvus。
知识和索引信息放在客服业务模块中；需要更大索引规模时再替换检索存储。
业务接口、schema、service、models 和 workflow 放在同一模块，页面按客服业务组织。
公共 AI 层只在真实复用或必要兼容问题时调整，不增加工作流 DSL 或基类。

后台权限由后端确定，普通客户不能管理知识或查看他人的订单、会话和运行记录。
工具的用户身份只能来自服务端上下文。
中断恢复校验记录 owner、module、待恢复状态和选择的订单，并持有同一 thread 锁。

无密钥时提供可运行的演示数据与明确标注的演示检索/模型路径；
真实语义向量、Agent 工具选择和重排效果需要模型与 embedding 权限另行验证。
参考系统的原始 300 题评估集未提供；本项目自带的示例评估数据必须标注来源，
不能把示例指标描述成参考系统或真实生产评估结果。
人工接管以应用内工单体现，不未经授权向外发送消息。

## 关键验收

- 知识问答引用真实已授权知识片段，不捏造引用。
- 查询订单与物流后接着问退款，关联正确订单并引用退货规则。
- 不明确订单时暂停；点选后继续；另一用户不能读取或恢复。
- 未收录问题不编造答案，进入待审池；审核补充后能在下一次问答检索到。
- 普通客户访问后台 API 返回拒绝，订单工具不能越过 owner 过滤。
- 四种检索策略指标由实际运行计算，未运行和演示状态清晰可见。
- 新业务迁移、OpenAPI 类型生成、后端与前端检查，以及 Docker 页面/API 验收通过。
